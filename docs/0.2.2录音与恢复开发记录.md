日期：2026-09-22；2026-09-23 继续验证。状态：**开发测试版**。

09-23 已完成完整 60 分钟原速回放、全部翻译和统一核查。**音频保存、流水线收尾和数据一致性通过本次稳定性检查；英文漏词、重复识别及中文忠实度仍未通过质量验收。** 修复了此次发现的纯标点字幕，使用全部已保存识别事件完成针对性复测，应用更新至 0.2.2 / build 6。以下保留 09-22 的阶段记录，并分别说明原始长测与修复后证据。

## 本轮变更

- VAD 保留 1 秒前置音频、0.5 秒判定余量和 0.25 秒尾部音频，减少语音开始被丢弃；保留样本计数和延迟事件统计。
- 麦克风输入独立接收、写入 WAV 并同步到磁盘，识别读取已保存数据；识别积压不再直接阻塞录音读取。支持仅录音、稍后识别。
- 原生暂停/继续会排空采样转换尾部，记录精确样本位置和墙钟时间。设备配置变化及休眠通知触发暂停，恢复由用户主动操作。
- 仅在已排空的静音边界或明确暂停处保存检查点。继续识别先核对音频及资源，保留已完成前缀，将不确定尾部归档后重做；无检查点时从头重做。没有保存任意位置的模型内部状态。
- SQLite 升级至版本 2；保留恢复历史，拒绝未来版本。界面每页最多 200 段，全局计数和完整导出保留全部段落。
- 每 5 秒记录工作进程内存/CPU 数据；长时脚本另记录 Ollama 进程、系统交换空间及热限制信息。

## 2026-09-22 提前停止的长时测试（历史）

计划 60 分钟，使用同一 TED 录音重复拼接并在轮次间加 2 秒静音。因用户要求节省额度、上传并收尾，已在 **24.97 分钟（1498 秒）**后主动停止，不能计作 60 分钟验收通过。

- 已提交音频：23,968,000 样本；停止后保存尾部耗时约 1.09 秒。
- 已保存英文：341 段；中文完成 339 段，待译 2 段，失败 0 段。待译尾段可用“继续补译”处理。
- ASR 队列峰值：4.602 秒；运行阶段端到端积压 P95 约 4.50 秒。
- 采样观测到的工作进程 RSS 峰值约 3.76 GiB，最后约 2.80 GiB。RSS 不等于 GPU 独占显存，未测量硬件功耗。
- 最终状态为 `stopped`，`asr_complete=false`。保存的源音频仍有未识别部分；没有将主动停止标成识别完成。

### 有证据的修复与针对性复测

确定性的实现问题是 **9 个纯标点片段产生字幕与翻译任务**。`segmentation.py` 现在只为含字母或数字的片段创建字幕，保留语句中的标点、真实重复和数字；所有原始识别事件仍留在数据库。该规则同时支持 Unicode 字母及汉字。

- 新增回归覆盖分包句点/省略号、真实重复、3.14、EOF 和原始事件保存；全部 Python 回归 **45 项通过**。
- 将原长测 **4,846 个事件**按原序号在新目录重放，得到 **832 个含文字字幕**；与原始 832 段逐项比较，英文、开始/结束时间、分句原因完全不变，无待提交尾部。原来的 9 个纯标点不再产生翻译任务。
- 重放后 TXT/SRT/VTT 各 832 段。该复测没有重跑模型、没有重新翻译，832 个新翻译任务处于 pending 是预期状态；原始 60 分钟任务仍保留 841/841 已完成结果，未覆写。
- 此修复位于模型之后，不会修复上述漏词、幻觉或时间戳异常，也不会改变其 WER。修复后的包未重新做一小时推理；其证据是确定性事件重放和回归测试，不能冒称 build 6 已重新通过完整长测。
- Swift 源码未变，沿用 14 项已通过证据；新的 Release 构建、包内运行时代码一致性及签名另行核对。首次受限环境打包停在系统图标转换，随后在具备系统访问权限的环境中完成打包。
