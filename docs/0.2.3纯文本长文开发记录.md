## 实现

- `Sources/TranslatorCore/LongTextTranslation.swift`：分段、UTF-8 半开区间、当次任务状态、串行控制器与统一导出。优先段落/句子边界，再按空白和 Swift Unicode 字符边界切分；不删除重复句，空白仍归入对应原文范围，但不会单独向模型请求翻译。分段与导出拼接在后台任务执行。
- 原文请求每个 UTF-8 字节保守估算为一个 token，译文估算预留原文字节数的两倍。固定上下文 8,192、输出上限 4,096、提示预留 1,024、余量 512，单次原文最多 2,048 UTF-8 字节；实际提示长度连同消息框架也校验。**这是估算，不是精确 tokenizer 计数。** 整篇文章不受旧 8,000 字符限制；单个异常巨大字素无法安全切分时明确报错，原文仍可导出。
- 文字页面直接异步复用 `OllamaEngine`，保留回环地址校验、拒绝重定向/云模型、已安装模型检查、正常结束标记、截断检测、空译文检测及核对提示。文档和原生语音仍使用原有工作进程路径。统一的单次预算也约束 CLI 和文档选段，超过时明确报错。
- 每轮固定原文、模型和方向，以 UUID 隔离异步返回。默认串行处理；停止立即标记当前段中断、取消本轮 URLSession 请求，不再调度后续段，不停止共用 Ollama。即使可控翻译器忽略取消并迟到返回，也不能修改新任务。
- 独立截断/不完整响应可记为失败后继续其他段；本机服务不可达或配置/模型校验失败会停止后续调度。没有自动重试、单段重试或自动重开。
- 页面显示总段数、完成、处理中、待处理、失败、中断数量，完成段即刻可读。复制仅包含完成译文；TXT 使用点击时快照，逐段包含全部原文、完成译文和核对提示，未完成、失败、中断均明确标记。输入/方向/模型变化后清除旧文字结果，避免误配。
- 退出时明确文字结果不会恢复。关闭窗口先走退出确认，选择「返回应用」保留原窗口及结果；原有录音停止、等待收尾及保存行为保留。最终包也修正了页脚反馈，使复制和保存提示可以显示。

## 自动检查

`bash scripts/swift.sh test`：**22 项测试通过**，包括原有 14 项和新增 8 项。最终 UI 修正后再次完整通过。

新增检查覆盖：

1. 超过 8,000 字符的原文逐字节重建、UTF-8 范围连续、真实重复保留。
2. 段落、缩写、小数、URL、中文、组合字符、emoji、CRLF、超长无标点与大段空白；所有请求有界，异常巨大字素明确拒绝。
3. 提示、输出与安全余量的容量约束，中文多字节输入和过大提示拒绝。
4. 可控翻译器下的串行进度、处理中快照、独立失败继续、完成译文与导出一致。
5. 停止后保留完成段，迟到返回不能污染立即启动的新方向/新模型任务，也不再发起旧任务后续请求。
6. 服务不可用停止调度，零译文以及分段准备中停止也能导出完整原文。
7. 输入不匹配、取消、空/截断/未正常结束响应不记为成功（含已有流式协议测试）。

语音 Python 代码未修改，本轮没有重复 Python 全套或长时间语音回放。Release 构建有既有 Vendor/WhisperKit 警告，本轮新代码未出现编译错误。

## 限制与后续

本轮没有文字持久化、恢复、历史库、单段/自动重试；关闭后不能继续。停止后的重新开始会从第一段完整翻译，长期保存依赖用户主动复制或导出。

PDF/Office 整篇翻译、OCR 改造、复杂排版、术语管理、截图和新导入入口均未实施。语音漏词、异常重复、时间戳问题保持原状，0.2.2 的音频长测为历史证据，不冒充本轮测试。

完成状态只证明获得正常结束的响应。合成文章实测不构成专业翻译质量评估；仍需核对条件、数字和否定关系，不保证跨段上下文或术语一致性。7B 本轮未推理，其他模型的特殊 tokenizer、完整断网、超大型书籍、多台机器、真人录音和新的长时语音运行均未验收。预算是保守估算，复杂 Markdown 按纯文本处理。
