# 0.2.7 文字、文档保存恢复开发记录

日期：2026-10-02。第一轮按[任务书](下一阶段-文字文档自动保存与恢复任务书.md)实施，最终交付为 **0.2.7/build25**。本记录对应文字长文、PDF/TXT整篇及显式OCR保存恢复；第二轮质量优化和第三轮实体故障验收尚未开始。0.2.3–0.2.6旧报告保留原结论，旧“暂缓持久化”仅为当轮范围。

## 1. 已实施功能

- 文字输入草稿、完整原文、稳定分段及UTF-8范围、方向、模型、实际配置、成功译文、错误、尝试次数和进度自动保存。
- 文档保留物理页清单、选定范围、提取方式、原始OCR观察与置信度、有效文字修订、人工核对状态、未应用编辑草稿、来源映射及完整翻译计划。
- 文字和文档页均提供“打开已保存任务”。列表显示类型、名称、更新时间、方向及进度；打开只读，中断状态转成可解释的停止状态，不启动翻译或OCR。用户主动继续才处理缺失页及待处理、失败和中断段。
- 成功段原样保留，当前半段可安全重做。失败段每任务累计最多三次尝试，每次用户继续只尝试一次；整体服务不可用或保存失败停止后续调度，不无限自动重试、不关闭已有Ollama。
- 改原文、方向、模型、有效OCR修订或重新开始时，旧任务先保留，新结果另归属。控制器除UUID外另有请求代次，阻止同UUID重开后的迟到响应、重复点击、旧准备结果污染当前任务。
- 原PDF/TXT复制到任务目录，校验大小与SHA-256；原路径只作来源记录。移动原文件不影响已保存文字和原页回查。副本身份不符时保留原文/译文，禁止混用来源和继续提取。原文件不改写。
- 失败提示、未落盘/已保存时刻、正常退出等待保存、保存失败返回应用或明确退出已接入。部分、停止、零译文、输入草稿仍能完整TXT导出；OCR导出包含原始识别及有效修订，不混入尚未应用的草稿。

存储与控制器位于[TaskRecovery.swift](../Sources/TranslatorCore/TaskRecovery.swift)、[LongTextTranslation.swift](../Sources/TranslatorCore/LongTextTranslation.swift)、[DocumentTranslation.swift](../Sources/TranslatorCore/DocumentTranslation.swift)；应用接入位于[TaskRecoveryUI.swift](../Sources/TranslatorApp/TaskRecoveryUI.swift)、AppState、WorkspaceView、DocumentWorkspace及LocalTranslatorApp。没有重建通用任务平台，也没有迁移录音数据库。

## 2. 保存格式与第二轮配置交接

正式目录：`~/Library/Application Support/LocalTranslator/TextDocuments`。每任务一个UUID目录，包含：

```text
<UUID>/
  current.json
  previous.json                  # 经过验证的上一快照
  source-<SHA256>.pdf 或 .txt      # 文档任务的源副本
```

`current.json`和`previous.json`采用schema **1** envelope：`schema`、`checksum`、`payload`。`payload`是Codable JSON Data（外层编码为base64），`checksum`为payload SHA-256。payload含任务UUID、单调revision、时间、类型与名称、configuration、完整input、文字job、document、drafts、asset。文档原始路径、指纹、页修订和段来源均保留。

存储actor后台串行校验和写入，临时文件原子替换后同步文件；先保存已验证predecessor，再提交current。旧revision被拒绝，重新开进程也从current恢复高水位。当前损坏时明确读取有效previous并警告，损坏文件保持原样且不能被新保存覆盖；应导出后新建任务。未知未来schema即使payload结构变化也拒绝，不偷偷降级读旧previous。没有自动修复、迁移或完整资料库管理UI。

翻译配置 `TranslationConfiguration.version=1`，`splitterVersion=natural-language-utf8-v1`。保存模型名、取得时的本机模型digest、方向、promptProfile、完整systemPrompt/userPrefix、options、keepAlive和disableThinking。HY-MT2默认profile为`hy-mt2-faithful-v1`，temperature 0.7、top_p 0.6、top_k 20、repeat_penalty 1.05、num_ctx 8192、num_predict 4096。本轮没有质量调参。配置按排序JSON计算SHA-256 binding；真实模型结果记录同一binding。未启动草稿尚未取得digest时明确为nil，启动前补绑定；已知digest不匹配则停止，不静默换模型。

**第二轮应增加明确配置/profile版本并保留旧recipe执行路径。** 重开旧任务继续使用已保存实际值及原计划；新默认值不能重写旧任务，也不能复用不匹配译文。当前validate仅支持配置version1和现有容量/分段规则；不兼容配置仍可阅读导出，不能继续。`TranslationRecord.configurationBinding`为可选以兼容未携带该字段的既有模型记录；本轮实际Ollama结果均携带binding。

文档提取profile为`pdfkit-vision-v1`，保存OCRSettings与方向。未知profile不能继续提取。build23预发布快照缺少新增可选profile/settings时沿用当时相同默认值；这一兼容仅用于本轮候选，不宣称通用格式迁移。

## 3. 保存边界、延迟与故障含义

草稿采用 **350毫秒防抖 + 后台排队 + 编码/磁盘写入耗时**。防抖不是绝对最大未落盘时间：持续输入会重置计时，系统权限等待、慢盘或较大快照可进一步延长；窗口显示有未落盘内容。切换和正常退出有显式flush，不依赖防抖完成。

模型请求前保存processing边界，完整结果与completed状态在同一快照提交，保存成功后才推进下一段；终态completed也等待提交再发布。异常退出保证已持久化成功段/页；当前生成中的半段、完成但尚未提交的一段/页可能重做，未落盘输入/校正草稿可能丢失，不承诺零缓冲损失。保存失败及时停止推进，内存完整结果仍供导出；不虚报已保存/全部完成。

后台保存测量（完整原文16,800 UTF-8字节、9段、模拟完整成功结果、30次同步原子快照）：中位数 **2.899毫秒**，P95 **4.047毫秒**，样本最大 **13.858毫秒**。注入写入闭包同时检查非主线程。不是大文件最坏延迟保证；每次快照重写，任务越大耗时可能增加。

最终build25测试进程在PDF第3段处理中SIGKILL；落盘为2成功、1处理中、9待处理，距最后有效快照 **11.378毫秒**。重开显示2成功、1中断、9待处理，主动继续后完成。这个时间只描述本样本。build23另有13毫秒样本，不能外推为任意系统崩溃、断电或真实磁盘满的保证。
