## 5. 实现与保存兼容

Swift统一从 `TranslationConfiguration` 构造请求，记录实际提示、参数、digest、分段/上下文版本及 `requestConfiguration`。新默认v2只作用于新HY任务；无显式配置的CLI也使用v2。旧v1仍可读取和执行，新增可选contextVersion在v1编码时省略，旧recipe编码与binding不变。版本、方向、模型、glossary不配、未知上下文或预算不配先拒绝；模型缺失、digest变化或非本地资源明确报错，不下载、不换模型、不关闭校验。

文字“重新开始”先保存旧任务，建立新ID并清除旧job，再等待模型元数据，避免已排队autosave把旧结果挂到新recipe。文档“从头重新翻译”先fork捕获旧配置/成功结果，再发布新recipe。打开旧任务仍沿用原计划、原配置和原选择模型；明确重译才创建新UUID采用当前profile，**不会强制把旧1.8B任务换成7B**。OCR重译保留原始OCR、有效文字修订、核对标记和来源映射。

Python增加 `translation_config.py`；新run/record任务写入完整v2recipe，翻译队列claim前核验本机模型并绑定digest。没有recipe的旧字幕任务按已知历史v1、保存digest和已有结果profile恢复，遇到不兼容证据拒绝继续，不套新默认。已有成功result_json不会被补写或重译；缺失的旧证据不能事后证明历史请求参数或权重，只保留原有证据并明确按历史规则继续。录后独立校对任务继承父任务recipe，未修改识别推理。

字幕claim携带configuration_binding，finish同事务核对当前配置、job与result binding，同时保留原修订/租约校验。首次允许补未知digest，禁止替换任务中已有配置。界面显示任务保存模型和“补译沿用任务保存的配置”，避免顶部新任务模型选择造成误解。原文警告增加期限/否定/必要条件/频率提醒，明确数字一致也不保证正确。

### 供0.2.9接续的格式约定

- 文字/文档仍在 `~/Library/Application Support/LocalTranslator/TextDocuments/<UUID>/`：`current.json`、`previous.json`、`source-<SHA256>.pdf/.txt`。envelope仍为schema1，checksum为payload SHA-256，payload是Codable JSON Data的base64。原子替换、sync、单调revision及上一有效版本规则不变，无需迁移。
- Swift task.configuration保存完整recipe；成功结果的configurationBinding对应原配置，requestConfiguration保存实际请求证据。源文、方向、模型、参数、有效修订不匹配不得复用成功结果；新任务与旧任务结果归属分开。
- Swift legacy version1保持原字节表示；new HY version2采用none-v1。未来提示/分段/上下文优化需新版本或新recipe并另建结果归属，不能覆盖历史完成译文。
- Recordings SQLite `PRAGMA user_version`仍为3，没有新增表迁移。完整recipe与digest保存在metadata，结果保存实际请求证据，job租约与binding共同校验；备份仍需整个任务目录及WAL收尾。
- 打开任务不启动推理；用户主动继续仍保留成功段。资源不兼容的数据仍可阅读/导出，恢复原模型或另建任务后再处理。
- 第一轮350毫秒输入/OCR草稿防抖、后台排队/磁盘耗时及异常退出未落盘边界仍适用；本轮不承诺缓冲零损失，不把本轮正常重开当作实体磁盘故障验收。
