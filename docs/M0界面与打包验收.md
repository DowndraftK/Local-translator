应用内不重复包含模型。文字翻译使用现有 Ollama 模型，语音默认读取本项目 `models` 目录。服务未运行时可在“本机资源”启动；模型移动后可重新选择目录。应用退出时会停止自己启动的 Ollama，原本已运行的服务不受影响。

## 当前交互边界

- 文字：每次最多 8000 字符，完成后显示译文；尚未将流式 token 逐个显示到界面。
- 文档：提取、选段翻译及单段保存；尚未实现整篇任务、原版排版导出和复杂表格还原。
- 录音：导入文件、逐片段显示、停止、双语 TXT 导出；“打开原录音”使用系统默认播放器，尚无应用内按时间点播放。
- 数据：测试原文、结果与日志保存在系统临时目录；显式导出用于长期保存。尚未实现持久资料库或自动续跑。
- **麦克风实时录音翻译：当前没有实现采集与实时调度，无法使用属于已知功能缺口。**

## 实时录音的难点与实施方案

本机已经执行过 Whisper 与 HY-MT2 的实际推理，短样本吞吐具备继续实现实时分句字幕的依据，但不能替代持续课堂录音测试。当前文件任务按约 15 秒独立窗口处理，且每次任务启动工作进程；实时模式需要持续采集和常驻处理。

| 部分 | 必须解决的问题 | 下一步实现 |
| --- | --- | --- |
| 采集与原音频 | 模型加载、推理、错误不能阻塞麦克风采集，原声音不能随失败丢失 | 显式麦克风权限、输入设备状态、采集回调与推理解耦，音频持续落盘 |
| 停顿与分句 | 停顿不总是句末；固定窗口会截断退款条件等句子 | VAD、滚动重叠窗口、草稿与稳定片段状态，保留未完成句子 |
| 去重与修订 | 同一句会被反复识别，后续音频可能修正前文 | 按时间及文本对齐，稳定后提交；为片段保留版本，迟到译文不能覆盖新内容 |
| 中文队列 | 每次草稿变化都翻译会造成浪费和积压 | 完整稳定句子进入翻译队列；限制并发与队列长度，显示落后时长 |
| 模型准备 | 首次加载可能接近两分钟，不能把这段时间藏在“录音中”状态 | 先明确显示准备状态并预热，随后复用常驻模型实例 |
| 停止与异常 | 点击停止后还有未确认尾句；设备断开、睡眠或服务失败可能造成缺口 | 完成尾句和保存检查点，标记录音缺口，提供保留原音频后的恢复路径 |

已核对项目固定版本的 `AudioStreamTranscriber`：它提供麦克风流式转写、VAD 判断以及 confirmed/unconfirmed 状态，可复用作原型基础。它不是完整双语录音应用；其停止接口当前只停止采集，项目仍需补齐尾句处理、音频持久化、中文队列和有界内存验证。不能简单接上该类后就宣称全部实时验收通过。

下一轮先实现“准备模型 → 开始录音 → 显示英文草稿/稳定英文 → 显示对应中文 → 停止并保存”的最小链路。先用可重复的分段合成音频测试边界，再由用户在应用内主动开启麦克风，验证 5–10 分钟自然英语；随后扩展到课堂距离、口音、噪声、60–90 分钟、断网及中断恢复。

## 重新打包

在项目目录运行 `bash scripts/package-app.sh`。输出目录带时间戳，不覆盖之前的构建。图标转换在受限自动执行环境中曾报告 Invalid Iconset，使用正常 macOS 权限后成功；这是打包工具环境问题，应用启动和功能测试已另行验证。
