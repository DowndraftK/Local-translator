1. 审查现有权限、设备通知、休眠通知、写盘错误与工作进程退出路径。复用现有自动检查，只为实际发现的问题补充必要回归。

5. 纳入前两项新增的文字/文档保存和配置路径，复用其已有有效证据；更新初版使用说明、验收清单和恢复办法，统一打包正式初版。固定模型配置及接受的质量限制保持，提交结果必须与实际证据一致。

外置设备不存在时，不能把系统默认设备切换或通知注入称为拔插验收通过。系统通知模拟不能代替真实休眠，异常注入不能代替真实空间不足。受设备或系统条件限制的项目需明确记录，并在最终交付前由用户决定是否接受该具体未验证项。

每项记录实际包版本、测试目录、触发/恢复时间、UI状态、采集事件、最后有效落盘样本/快照和恢复结果。录音可读性、数据保留、识别完成与语义准确分开，不把最后缓冲未落盘解释成已保存数据丢失，也不隐瞒最大未保存范围。

已接受的翻译限制无需再次请求接受，也不作为缺失的第三轮故障证据。设备或系统条件导致的未验证项另行记录并由用户决定，不能将“接受模型误译限制”解释为接受数据丢失、虚假状态或跳过实体故障场景。

## 5. 实机配合与保护边界

麦克风录音由用户在应用中主动开始，设备拔插、权限变化和休眠由用户配合执行。进入这些步骤时一次说明操作与预计等待，不在用户不知情时开始录音或使整机休眠。

磁盘空间不足采用隔离的小容量测试存储；不填满系统盘、不删除用户文件、不破坏唯一数据库或模型。先准备可核对的测试方案与目录，再执行涉及挂载或系统环境的必要操作。若系统权限阻碍，则具体说明，不能把模拟结果写成实机通过。

不得为拒绝权限场景重置整机或所有应用的隐私授权；用户只调整本应用相关权限。签名/安装变化可能影响系统授权身份，应记录最终候选包实际表现，不能用旧测试包身份代替新包验收。

原历史录音、SQLite、完整字幕、模型、日志及唯一证据只读。新试验使用独立任务和已忽略目录，验收结束清理本次创建的临时挂载及进程；保留可恢复的验收证据。不停止原本已运行的 Ollama，不下载新模型或新增服务。GPU 模型任务串行，不遗留调度器或后台长测。

UI 通过已提供的电脑操作工具控制；不使用 AppleScript 等旁路操作。只对必要的故障操作协调用户，不为已授权的常规审查、修复或打包重复确认。
