日期：2026-10-01。状态：第三轮任务书已编制，实机验收尚未开始。目标版本 **0.2.9**，依赖0.2.7保存与恢复及0.2.8质量优化交付，见[三个任务安排](正式初版-三个任务安排.md)。

## 1. 用户决定与交付目标

本任务完成“实体故障与恢复验收”和必要修复，最后交付当前Mac上的个人自用正式初版。前两轮分别实现文字/文档保存与恢复、翻译质量评审与有限优化，本轮对两轮后的实际应用做故障验收。此前只做故障验收即可发布的范围已被替代。

本次初版包含已有文字、PDF/TXT、显式扫描PDF OCR、麦克风/文件字幕、录音保存、补译、回放、录后校对和TXT/SRT/VTT，以及前两轮新增的自动保存/恢复与经评审默认翻译配置。保留当前本机模型、Python环境和固定源码依赖，不扩大为包含模型的独立安装发行版。版本继续0.2.x规则，正式初版为0.2.9，不自动跳到1.0.0。编制时实际包仍是0.2.6/build21，任务书不代表未来版本已交付。

真实麦克风质量专项、60–90 分钟课堂综合测试、真实文档全面覆盖和完整断网/外连审计退出本轮范围。文字/文档保存恢复及有限翻译质量优化在独立任务中完成，本任务验收其故障与恢复路径，不重复开展全面模型评选。Office 整篇、复杂排版、术语库、完整资料库、快捷阅读和新增导出不开展。未执行项目保留为限制，不写成通过。短录音仅验证数据保留和恢复，不扩展为识别准确率评测。

## 3. 实施顺序

1. 审查现有权限、设备通知、休眠通知、写盘错误与工作进程退出路径。复用现有自动检查，只为实际发现的问题补充必要回归。
2. 用新建短录音任务建立正常开始、暂停、继续、停止、回放和重开基线，记录采集事件、落盘样本和任务状态。
3. 依次执行下表故障场景。每次独立记录触发方式、观察结果、原音频和数据库证据；修复后只复测受影响场景及相应正常路径。
4. 用最终候选包重做必要的故障检查，避免仅验证开发环境。核验版本、签名、包内代码、ZIP 和简短主流程操作。
5. 纳入前两项新增的文字/文档保存和配置路径，核对前两项交付已完成，再更新初版使用说明、验收清单和恢复办法，统一打包正式初版。提交结果必须与实际证据一致。

## 4. 验收矩阵

| 场景 | 实际操作与证据 | 通过条件 |
| --- | --- | --- |
| 正常暂停与继续 | 短录音中明确暂停、等待、继续、停止；比较事件样本、保存 WAV 和回放 | 暂停墙钟不进入媒体时长；已接收音频和尾部正常保存；重开可读，状态没有假录音 |
| 首次拒绝权限 | 用户在真实权限提示中拒绝；已存在授权时用系统允许的方法在用户配合下准备场景 | 明确说明无权限和开启办法；不显示正在录音，不启动实际采集，不产生假完成结果；授权后可再次开始 |
| 权限撤回与恢复 | 用户通过系统设置撤回权限，再按系统实际生效方式操作应用并重新允许 | 清楚记录 macOS 是否终止应用或仅阻止采集；已落盘内容能找回；无权限时不能假继续；重新授权后状态可恢复 |
| 外置麦克风断开/切换 | 用户在测试录音中拔下已有外置输入设备，再接回；记录设备配置变化 | 停止或暂停有效采集并提示；已保存内容保留；不静默假装连续采集；设备恢复后用户可主动继续或另建任务 |
| 真实休眠与唤醒 | 用户在短录音中使整机实际休眠并唤醒；比较系统事件和录音事件 | 休眠前已接收内容尽可能排空；休眠缺口明确，媒体时钟不填入假声音；唤醒后由用户主动继续，停止/重开正常 |
| 实际写盘空间不足 | 在容量受限、可清理的独立测试存储中实际触发空间不足，分别考虑 WAV/状态记录/数据库写入 | 明确报告保存失败并停止相关录音；保留已持久化内容；不能虚报完成或可无限继续；释放测试空间后可读取/恢复有效内容，不能覆盖原任务 |
| 应用/录音工作进程异常退出 | 只终止本次测试创建的应用或工作进程；重开测试任务，继续识别/补译 | 恢复位置不超前于可验证音频；成功前缀保持，待处理尾部安全重做；不重复事件、不用旧回调覆盖新任务；原版和恢复历史保留 |
| 文字/文档处理中异常退出 | 使用0.2.7保存路径的新测试任务，含PDF范围和OCR校正；处理中终止测试应用后重开 | 已持久化原文、校正、成功译文、配置和来源保留；处理中段转为中断，用户继续只处理未完成部分，成功段不重译 |
| 文字/文档实际保存空间不足 | 隔离存储中触发源副本、快照或数据库保存失败；释放测试空间后重开 | 写盘失败明确可见，不覆盖最后良好版本，不虚报已保存；可恢复数据与报告一致，导出覆盖全部已取得原文 |
| 新配置与旧任务恢复 | 打开保留的0.2.7/0.2.8测试副本，比较配置与成功结果，明确续译或重译 | 原成功结果不自动改变；原配置可用则继续，缺失则报错；新默认不冒充旧结果来源，重译保留原版 |
| 最终包使用 | 最终候选包正常启动，短录音保存/重开/回放/导出，文字与 PDF/TXT 有限操作 | 故障修复没有破坏已有入口；版本、实际构建与说明一致；导出保留已完成内容和真实未完成状态 |

外置设备不存在时，不能把系统默认设备切换或通知注入称为拔插验收通过。系统通知模拟不能代替真实休眠，异常注入不能代替真实空间不足。受设备或系统条件限制的项目需明确记录，并在最终交付前由用户决定是否接受该具体未验证项。

每项记录实际包版本、测试目录、触发/恢复时间、UI状态、采集事件、最后有效落盘样本/快照和恢复结果。录音可读性、数据保留、识别完成与语义准确分开，不把最后缓冲未落盘解释成已保存数据丢失，也不隐瞒最大未保存范围。

## 5. 实机配合与保护边界

麦克风录音由用户在应用中主动开始，设备拔插、权限变化和休眠由用户配合执行。进入这些步骤时一次说明操作与预计等待，不在用户不知情时开始录音或使整机休眠。

磁盘空间不足采用隔离的小容量测试存储；不填满系统盘、不删除用户文件、不破坏唯一数据库或模型。先准备可核对的测试方案与目录，再执行涉及挂载或系统环境的必要操作。若系统权限阻碍，则具体说明，不能把模拟结果写成实机通过。

不得为拒绝权限场景重置整机或所有应用的隐私授权；用户只调整本应用相关权限。签名/安装变化可能影响系统授权身份，应记录最终候选包实际表现，不能用旧测试包身份代替新包验收。

原历史录音、SQLite、完整字幕、模型、日志及唯一证据只读。新试验使用独立任务和已忽略目录，验收结束清理本次创建的临时挂载及进程；保留可恢复的验收证据。不停止原本已运行的 Ollama，不下载新模型或新增服务。GPU 模型任务串行，不遗留调度器或后台长测。

UI 通过已提供的电脑操作工具控制；不使用 AppleScript 等旁路操作。只对必要的故障操作协调用户，不为已授权的常规审查、修复或打包重复确认。
