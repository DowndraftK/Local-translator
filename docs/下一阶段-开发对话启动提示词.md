## 本轮只做四项功能

使用入口为“文字翻译”页面，粘贴纯文本文章，沿用英中/中英方向和现有本地模型选择：

1. **长文本自动分段**：支持超过当前 8,000 字符限制的整篇输入，按段落、句子和安全模型容量拆分，保留完整原文、真实重复和顺序。
2. **逐段显示译文**：每完成一段就显示，不必等整篇结束。段内逐字显示不作为本轮必做要求。
3. **明确的整体进度**：显示总段数、已完成、处理中、待处理、失败等状态，停止状态明确；部分失败不能标为全部成功。
4. **完整双语导出**：支持复制已有译文及按原文顺序导出双语 TXT；包括所有原文和已完成译文，对失败、未开始及停止中断段明确标记。Markdown 可复用实现补充，PDF/Office 排版导出不在本轮。

## 实现时必须注意

- 现有文字 UI 在 `Sources/TranslatorApp/WorkspaceView.swift` 的 `TextWorkspace`；调度在 `AppState.swift`，目前经 CLI 等整次翻译结束，使用临时目录。
- `Sources/TranslatorCore/OllamaEngine.swift` 已有本地校验、流式响应与回调；`Types.swift` 有翻译结果及核对提示。优先复用，根据实际条件选择直接调用或已有子进程，不引入新的服务或数据库。
- 整篇 8,000 字符上限可以调整，但不能删除单次容量保护就把整篇送入模型。预算应考虑提示、输入、输出和余量；字符数不等于 token 数。超长句、无标点输入必须有安全兜底，原文能按顺序完整重建。
- 默认串行调用模型。运行时固定输入、方向和模型，避免新旧结果混用；旧任务的迟到回调不得覆盖新任务。
- 点击停止后不再发起后续请求，保留已完成译文；取消或截断的当前片段不能冒充成功。单段失败或本地服务不可用要有清楚状态，不做隐式重试。
- 保留原有本机端点限制、模型校验、截断检查、核对提示和取消行为。只管理本次操作拥有的工作进程，不停止用户共用 Ollama。
- 退出提示应准确反映文字任务不会自动恢复，同时保留录音已有的保存和退出行为。其他页面保持原有功能。
