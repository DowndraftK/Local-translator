日期：2026-09-27，状态更新于 2026-09-29。**本轮四项能力、自动检查、有限真实 Vision／本机模型验证及最终包操作验收已完成，交付 0.2.5 / build 13。** 当前功能、证据、模型质量问题及未完成验收见 [0.2.5 开发记录](0.2.5扫描型PDF开发记录.md)。下文基线和要求保留为原始范围依据；按用户 09-29 最新指示，Git 上传不再核对本地或远程 SHA。

## 1. 为什么安排这个节点

0.2.3 已完成纯文本长文，0.2.4 已完成文字型 PDF 的范围提取、串行翻译、按页阅读和完整 TXT 导出。现在用户遇到扫描页或正文为图片的页面时，整篇流程仍无法获得正文；旧 OCR 入口只能提取和逐段翻译，不能复用新的完整阅读流程。

本轮把已有 Vision OCR 接入现有文档任务，并提供识别后的核对与必要校正。它是总体规划 T10/T12 的受限增量，不是一次实现完整混合版面解析。0.2.4 中 OCR 的暂缓只在本节点明确限定的范围内解除；其余暂缓项不自动恢复。

目标路径：

**选择 PDF → 明确选择文字层或 OCR → 设置物理页范围 → 逐页识别 → 查看原页并核对/校正识别文字 → 启动范围翻译 → 按页双语阅读 → 导出带识别来源和问题记录的 TXT。**

## 3. 本轮只做四项能力

| 必交付能力 | 用户能做什么 | 完成条件 |
| --- | --- | --- |
| 显式 OCR 范围提取 | 在文档整篇页主动选择 OCR，处理全部或一个连续范围 | 默认文字层不变；OCR 按真实物理页处理，不再依赖前 N 页接口 |
| 逐页识别预览与核对 | 查看原 PDF、识别文字、来源、提示；翻译前校正 OCR 原文 | 原始识别结果保留，人工编辑单独标记，校正后重新安全分段 |
| OCR 接入整篇翻译与阅读 | 将当前识别/校正快照整篇翻译，逐段阅读并停止 | 复用已有串行调度和预算；固定识别模式、来源版本、方向及模型，旧回调不污染新任务 |
| 来源完整的双语导出 | 复制完成译文，导出识别结果、校正原文及已有译文 | 逐页清单、原始 OCR、实际翻译原文版本、问题和未完成状态均可追溯 |

已有文字型 PDF/TXT 功能保留，不重新实现分段、调度、双语阅读和基础导出。仍使用现有「文档与图片」页，不增加独立产品页面。

## 4. 明确的范围边界

### 本轮支持

- 印刷体、正向、清晰、简单单栏的英语和简体中文扫描 PDF。
- 用户主动选择对某个连续物理页范围做整页 OCR；范围可以只含一页。
- 有文字层的 PDF 也允许用户主动选 OCR，用于处理“有页眉文字但正文在图片中”等情况；该模式对所选每页整体渲染后识别。
- OCR 结果按页核对，翻译前对当前页文字作必要人工修正。
- 文字层模式、OCR 模式分开运行；TXT 保持 UTF-8 路径，不显示无意义的 OCR 选项。

### 继续暂缓

自动扫描检测/自动 OCR 回退、文字层和图像区域自动拼接、跨来源智能去重、任意离散页集合、选区 OCR、截图、图片拖放/粘贴等新入口；复杂双栏重排、表格/公式结构、手写体、自动纠偏和语言自动检测；DOCX/PPTX 整篇与原排版回写；HTML/PDF 双语排版导出；术语管理、资料库、任务持久化、历史、续跑、单段/自动重试；语音漏词、重复、时间戳和新的长时语音验收。

**尤其不做：** 把文字层内容与 OCR 输出直接相加，再按字符串相同与否删除重复。整页 OCR 是本轮该页翻译来源的替代模式；不自动混入另一模式的内容。真实重复文字仍保留。

## 6. 数据、范围及线程规则

### 6.1 每页数据与来源

逐页记录至少包括：物理页码、原页标签、模式（文字层/OCR）、识别状态、原始 OCR 文本、当前有效原文、是否人工编辑、原文修订 ID、核对状态、问题说明。

OCR 原始证据至少保留观察项 ID、识别顺序、文字、Vision 置信度、坐标和坐标系说明，以及本次渲染像素大小/方向。可以仅保留于当前任务内存；不增加自动落盘。置信度是识别器的启发式信息，不是整页准确率或完整性证明。

翻译片段的 UTF-8 范围必须明确指向**本轮有效原文及其修订**。未编辑时可关联 OCR 观察项；人工插入、删除或改序后，只保证页级来源和校正文本范围，不捏造逐字 PDF 坐标。原始 OCR 记录不随用户编辑被覆盖。

区分四个概念：已获得识别文字、用户已查看/确认、翻译响应正常完成、PDF 内容完整且准确。前三项都不能推导第四项。

### 6.2 范围与资源上限

- 沿用从 1 开始的 PDF 物理页码，最多 200 页/轮、256 MB/文件。支持 201–220；超范围、超量明确拒绝，不裁剪或跳页。
- 默认逐页串行识别，再复用串行翻译。识别与翻译分阶段，不要求边 OCR 边自动翻译，以便用户先核对文字。
- 在分配位图前限制像素尺寸。建议最长边最多 3,000 像素、总像素最多 9,000,000；开发时可依据现有实现调整，但必须有明确硬上限和验收记录，不只限制缩放倍数。
- 不缓存整书全分辨率位图；一页处理后释放图像/临时 OCR 对象。已有不可变源文件数据和 PDF 预览快照保留。
- 使用可见裁切区域，正确处理 PDF rotation/cropBox；非支持方向或复杂裁切必须有提示，不能翻译被裁掉的不可见文字而不说明。
- 文件读取、PDF 渲染、Vision 执行、分段、导出拼接/写盘不阻塞主线程。提取用 PDFKit 对象由明确的串行执行上下文持有；UI 预览使用独立对象。

### 6.3 状态与取消

页面至少区分待处理、识别中、有文字、未识别到文字、失败、停止未处理；当前页取消不得伪装识别成功。保留停止之前已经完整获得的页结果。

识别进度与翻译进度分别展示：所选页、完成识别页、无文字页、失败页、未处理页，以及翻译完成/处理中/待处理/失败/中断段数。

必须验证 Vision 同步执行的取消方式和线程要求。不能把取消消息排到同一个被 `perform` 阻塞的 actor 后面便宣称即时取消。应接入可用的请求取消机制，或明确显示当前页正在取消/等待底层返回；停止后不启动下一页，底层迟到结果不得写入当前或新任务。不要在取消后接受部分观察项为完整页面结果。

每次换文件、模式、范围、重新识别或重建校正计划都携带 UUID/修订隔离。检查旧 OCR 回调、旧分段回调和旧翻译回调三条路径。保持本机服务与模型校验、正常结束/截断检查，不停止用户共用 Ollama。

## 7. 核对、编辑与翻译规则

1. 默认继续使用文字层模式；无文字只提示可主动改用 OCR，不自动开始识别。OCR 模式必须在页面标题和导出中明确可见。
2. OCR 后展示每页识别原文、原 PDF 定位、核对提示。置信度较低的内容不能静默删除；可提示重点核对，但不强制逐页确认才允许翻译。
3. 第一轮翻译启动前可以编辑当前页 OCR 文本。明确提供保存校正/取消编辑，不因切页悄悄丢弃草稿；有未保存修改时禁止开始翻译，并清楚指出原因。无需自动校正、历史撤销栈或逐字符坐标高亮。
4. 保存校正产生新修订，在后台重建当前完整翻译计划；完成前禁止启动翻译。文字、标点、重复、空白保留可追溯范围；编辑为空的页面有明确“人工清空”状态，不算识别失败。
5. 开始翻译后，当前轮来源不可变，包含停止后保留的结果。想再次修改时，使用明确的“重新核对并开始新一轮”操作，先说明将清除当前译文，但保留原始 OCR 与当前校正文；旧完成译文不能继续挂在新原文上。不实现按段重译、续跑或修订历史库。
6. 模型、方向和模式锁定沿用已有运行时规则；停止不删除已完成译文，已有结果可继续阅读和导出。新一轮开始意味着重新翻译，不暗示续跑。
7. 识别没有获得文字的页不发送模型请求；用户手动补入文字后可翻译，但来源必须标为人工输入，不能把人工内容算作 OCR 覆盖成功。
8. 核对状态可由用户明确设置。修改后重置当前有效原文的核对状态；系统不得根据高置信度或翻译完成自动标为“已人工核对”。

## 8. 导出和退出

沿用标准保存面板和完整双语 TXT。导出采用点击时一致快照，至少包含：

- 文件名/身份、总页数、选择范围、提取模式、OCR 语言与渲染参数、模型、方向、任务状态和覆盖说明。
- 所选全部页的页码、原始识别结果、来源/核对状态和问题信息；无文字、失败、停止未处理页不可消失。
- 当前有效原文与修订标识，以及对应完成译文、失败/待处理/中断标记和核对提示。未编辑页可用一份文字同时标注“原始 OCR＝有效原文”；已编辑页分别输出两份有明确标签的版本，这属于有意保留证据，不是无说明的重复正文。
- 不把人工补字或删除后的版本叫作“原 PDF 完整原文”，也不把 OCR 成功叫作“全文准确识别”。文字层模式保持原有表述，OCR 模式不能继续显示“仅提取文字层、不执行 OCR”的静态提示。
- 复制仅包含当前修订下已完整完成的译文，不含生成中、旧修订或错误响应。

退出提示说明识别结果、校正文字、核对状态及译文均只保留于当前窗口，不会自动恢复；取消退出后这些内容仍可操作。现有文字页、录音页停止/保存/退出行为保持。

| 场景 | 必须观察到的结果 | 方法 |
| --- | --- | --- |
| 正常文字型 PDF/TXT | 默认不 OCR，0.2.4 范围和导出能力不回退 | 可控 OCR 调用计数＋原有回归 |
| 纯图像扫描 PDF | 明确 OCR 后获得逐页文字，末页仍在清单中 | 将自有已知文字渲染成真正无文字层的 PDF，再用真实 Vision |

| 有页眉文字＋图片正文 | 文字层模式不冒称覆盖；显式整页 OCR 有可追溯结果、不重复追加页眉 | 小型混合夹具，识别和视觉核对 |
| 无文字/低质量页 | 无文字及核对提示保留；不把置信度当完整性保证 | 纯图像/退化夹具及可控 OCR |
| 重复、Unicode、数字/否定、长识别段 | 全部识别输出可重建，每请求受预算保护 | 已知文字夹具＋分段/范围自动检查 |
| 旋转/裁切与大尺寸页 | 方向和可见区域有依据；位图上限有效，无整书位图缓存 | 90°旋转、裁切、异常大页面夹具；记录资源情况 |
| 人工修正/清空/补入 | 原始识别仍在，修订和来源明确；旧译文不会对应新原文 | 控制器及 UI 验证 |
| 保存草稿、切页、核对状态 | 未保存状态明确；保存后重建完整计划，人工核对不自动伪造 | UI 和状态测试 |
| OCR 中途停止及立刻换文件 | 停止后不调下一页，已有页面保留，迟到结果不污染新轮 | 故意晚返回的可控 OCR＋真实 Vision 小样本 |
| 翻译失败/停止/改源 | 失败不冒充完成，旧修订回调隔离，导出保持当前快照 | 可控翻译器；有限模型停止验证 |
| 完整/部分/零译文/仅人工原文导出 | 所选页全列出；识别原文、有效版本和状态可核对 | 对实际导出解析核对 |
| 退出后返回 | 原窗口和识别/校正/译文保留，退出文案准确 | 最终包操作 |

OCR 完整性分三层验证：已知页面可见内容与真实识别结果的差异、识别输出到有效原文的明确修订、有效原文到片段/导出的字节完整性。不能仅验证最后一层便宣称 OCR 覆盖完整。

## 10. 有限本机验证与交付

1. 运行 `bash scripts/swift.sh test`，记录新总数；故障和大范围用可控 OCR/翻译器，验证串行、取消、迟到回调及版本隔离。真实 Vision 的识别精度与确定性单元测试分开，避免把跨系统可能变化的 OCR 输出做成脆弱逐字断言。

4. 做一次中文 OCR→英文短范围验证、一次 OCR 或翻译中途停止后完整导出、一次人工校正后翻译。全部阶段分别记录成功与限制，不反复使用真实模型跑故障和极端场景。
