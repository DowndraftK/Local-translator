# 0.2.7 任务书：文字、文档任务自动保存与恢复

日期：2026-10-01。状态：第一轮已实施并完成最终包操作验证，交付 **0.2.7/build25**；实际检查、恢复格式与限制见[开发记录](0.2.7文字文档保存恢复开发记录.md)。后两轮尚未开始。以下保留开工范围与基线。

## 1. 目标与交付范围

在现有文字长文、PDF/TXT 整篇及显式扫描 PDF OCR 流程上，实现自动保存、打开已保存任务和继续未完成处理。正常关闭、停止或测试进程异常退出后，已持久化的原文、OCR 校正、成功译文和进度能够找回。

这是[正式初版三个任务](正式初版-三个任务安排.md)的第一轮。其后分别完成0.2.8翻译质量评审与模型优化、0.2.9实体故障与恢复验收，统一交付个人自用正式初版。本轮完成不宣称三轮已全部完成。

| 必做能力 | 用户可见结果 |
| --- | --- |
| 自动保存 | 输入/校正草稿及任务数据有清晰保存状态；成功段与任务进度持久化 |
| 最小任务入口 | 在文字/文档页面找到已保存任务，显示类型、名称、时间和状态，能打开 |
| 重开与继续 | 保留成功段，用户主动继续待处理、失败和中断部分；不从第一段全部重译 |
| 完整来源与修订 | 页范围、原始提取/OCR、有效校正和译文归属保持；原页仍可定位 |
| 保存错误处理 | 保存失败可见，不能宣称已经保存或全部完成；已保存内容可导出 |

不做完整收藏/分类/搜索资料库、账户同步、术语库、Office整篇、复杂排版、新增导出格式、全面模型评测或语音质量改造。不进行实体麦克风故障操作或新的长测。保留现有文字和文档TXT、录音TXT/SRT/VTT入口。

## 4. 保存设计与数据约束

### 4.1 最小持久数据

| 数据 | 最低要求 |
| --- | --- |
| 身份与格式 | 任务UUID、类型、存储schema版本、名称、创建/更新时间 |
| 原文与计划 | 完整输入、稳定段ID/顺序、UTF-8来源范围、页清单、所选范围、提取方式与问题页 |
| 配置 | 方向、模型标识、可获得的模型digest、提示/生成参数/分段规则版本及实际值；未知项明确标注 |
| 译文与状态 | 每段原文修订、结果、警告、错误、完成/待处理/失败/中断状态、任务进度 |
| OCR | 原始识别、有效校正、修订、核对状态、尚未应用编辑草稿及其归属 |
| 源资产 | 原文件身份、内容指纹、受管理副本或重新定位所需信息；定位与译文来源一致 |

选择适合现有Codable模型的原子快照或SQLite，由实现者按现有代码决定。任务状态和成功结果必须一致提交；如使用快照，保留可验证的上一份有效版本，写入失败不得覆盖唯一良好数据。拒绝不支持的未来格式；损坏数据明确报告，不静默清空或重建。

任务保存到`Application Support/LocalTranslator`内明确的文字/文档目录，不依赖系统临时目录。测试使用独立临时存储入口，不读写用户唯一历史任务。保存工作在串行后台执行，保证版本顺序，不能让旧保存请求覆盖新快照或阻塞UI。

### 4.2 草稿、结果与退出

输入及OCR编辑草稿采用短防抖自动保存，记录实际保存完成时刻/未保存状态；任务开始、段完成、停止与正常退出有明确持久化边界。不得将未收到正常结束标记的半段译文记成完成。

成功段仅在结果与状态成功保存后称为已保存。保存失败及时提示、停止继续推进不可持久化的任务，保留内存结果供用户导出；不以无限重试掩盖错误。正常退出等待必要保存收尾，失败时允许返回应用或明确选择退出。异常退出只能保证已持久化内容，报告最后有效保存边界，不承诺未落盘缓冲零损失。

### 4.3 原文件与OCR

推荐为本轮受支持的PDF/TXT保留受管理源副本，原文件不得被改写；复制与指纹核对在后台完成，并保留现有256MB文件/200页任务保护。也可采用持久访问与重新定位方案，但必须满足源移动/变更可见、原页可回查、已提取文字和译文不丢。

提取/OCR处理中异常退出，重开保留已完成页，未完成页明确标记。用户继续时仅处理尚未取得有效结果的页；已保存的人工校正和修订不得被重做OCR覆盖。校正草稿与翻译快照不同，重新翻译须以明确有效修订开始。

## 5. 恢复与续译规则

1. 打开任务只读取，不自动启动模型、OCR或翻译。中断的运行状态转成可解释的中断/待继续状态；任务总数和来源覆盖不变。
2. 用户主动继续时校验原文、计划、源资产与配置。成功且版本匹配的段保持；只调度待处理、失败或中断段。正在请求中的段可安全重做，不保存模型内部生成状态。
3. 保留有限的失败段重试入口；服务整体不可用时停止后续调度，不循环自动重试，不终止共用Ollama。
4. 修改原文、OCR校正、方向或配置不能混用旧结果。保留旧任务/修订，明确新一轮归属；当前显示与存储不得出现跨版本译文。
5. 旧请求迟到、重复恢复、两次点击继续和切换任务不能重复提交或覆盖新任务。恢复沿用原计划，不能随新分段器悄悄重排成功段。
6. 模型缺失、配置不兼容或源文件无法确认时保留数据并给出操作办法，不能悄悄换模型或重新翻译全部成功内容。
7. 导出读取同一持久化/已确认快照，包含全部所选原文、页面、有效修订和未完成标记；零译文、失败或停止任务仍可导出。
8. 开始新任务或切换任务后，之前的任务仍可找回；最小入口无需收藏、分类、全文搜索或复杂多窗口管理。

## 6. 工作包与验收

| 工作包 | 产物与检查点 |
| --- | --- |
| 存储格式与资产 | 格式版本、原子保存/读取、独立测试目录、源身份和损坏错误；原文件不改写 |
| 文字自动保存 | 草稿、分段、成功段和状态保存；正常重开与异常退出续译 |
| 文档/OCR保存 | 页范围、覆盖、原始与校正文字、草稿和修订保留；源移动/变更规则 |
| 调度与入口 | 打开、继续、失败段重试、配置绑定、旧回调隔离；仅未完成部分请求模型 |
| 导出与退出 | 完整/部分/零译文及OCR修订一致；更新“不恢复”的过时文案 |
| 实际包交付 | 新版本操作、检查记录、开发记录、README与Git提交推送 |

有意义的自动检查覆盖原子保存失败/损坏/格式版本、乱序保存、分段与来源、重开状态、成功段不重译、迟到响应和OCR草稿。使用可控翻译器/OCR，不把真实Vision输出写成跨系统固定断言。

运行`bash scripts/swift.sh test`，记录实际通过/跳过数量；修改Python或共享录音代码时再执行受影响Python检查。历史OCR通过可复用，本轮仅执行必要的有限真实OCR保存/恢复检查，不重做整轮OCR质量测试。

新包最低验收：超过8,000字符长文、至少12页简单PDF、少量扫描页人工校正、TXT、英中两个方向；完成/中途停止/测试应用异常退出/重开/继续/导出。有限真实模型串行，证明重开与续译实际接入，记录请求次数或段ID证明成功段未重译。人工内容质量不是本轮模型评选。

空间不足采用可控写入失败验证保存路径；真正磁盘不足、实体设备与休眠统一留到0.2.9，不以本轮模拟标为实机通过。
