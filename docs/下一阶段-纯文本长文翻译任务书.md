## 1. 本轮目标与用户决定

在原生 Mac 应用的「文字翻译」页面，实现“粘贴长文章 → 自动分段 → 逐段显示译文与进度 → 复制或导出双语结果”的当次使用流程。沿用英中/中英方向及已有本地模型选择。

用户已明确：连续漏词以后有时间再修；文字任务的“保存与继续”及相关持久化能力先不做。随后确认按以下四项功能推进，并要求准备任务文档及新对话提示词。**本任务书只准备交接，不代表已实现功能。**

| 本轮必做 | 交付效果 |
| --- | --- |
| 长文本自动分段 | 超过原有 8,000 字符总输入限制的文章，按段落、句子和单次模型容量拆分处理 |
| 逐段显示译文 | 每完成一段就能阅读该段，保留原文顺序及中英对应 |
| 明确的整体进度 | 能查看总段数、已完成、处理中、待处理和失败数量；停止状态明确 |
| 完整双语导出 | 按顺序导出完整原文与已有译文，缺失译文明确标记；支持复制译文和双语 TXT 导出 |

TXT 是本轮最低必交付格式；Markdown 导出可沿用同一文本导出逻辑补充，不以 PDF/Office 排版导出作为本轮验收条件。“逐段显示”要求每段完成即显示，不要求本轮额外实现段内逐字动画。

### 明确暂缓或不在本轮范围

- 文字任务自动持久化、关闭应用后恢复/继续、历史任务列表、恢复检查点、统一资料库。
- 失败段单独重试及自动重试。单段重试本可独立实现，本轮为了缩小范围也暂缓。
- PDF/DOCX/PPTX 等文档页面整篇翻译、OCR 改造、原排版导出、文件导入新入口。
- 术语表管理、新模型下载或模型参数批量评测。
- 语音连续漏词、异常重复、字幕对齐修复及新的 60/90 分钟回放。

当前窗口中的进度、译文、停止操作及用户主动导出仍需保留。临时工作文件或本地测试日志可以按现有实现使用，它们不构成可恢复的用户任务库。退出后的结果保留依靠用户主动复制/导出，不承诺自动恢复。

## 4. 行为要求

### 4.1 分段与容量

1. 放开的是整篇输入的 8,000 字符限制；每次模型调用仍必须在安全预算内。不能只删除字符判断就把整篇文章送给模型。
2. 预算应覆盖模型上下文、提示、原文、预计译文及余量，尤其考虑中英转换的长度变化。若没有准确 tokenizer，应明确采用保守估算，不能宣称精确 token 计数。
3. 优先按段落和句子拆分；缩写、小数、URL 等尽量完整。超长句或无标点长段需要有 Unicode 安全的兜底切分，不能卡住或超过容量。
4. 保留原文完整性和顺序，包括真实重复句、数字、标点和段落映射。分段后的原文范围应能重建输入；无需把纯空白作为独立翻译请求。
5. 仅做文本分段与翻译；Markdown 可作为普通文本输入，不在本轮承诺完整 Markdown 语法保护或复杂排版。
6. 本轮默认串行调用本地模型。处理长文时界面应可响应停止、滚动和查看结果，不因分段/拼接阻塞主线程。

### 4.2 当次任务与显示

1. 每段具有稳定顺序、原文、结果及状态。每段真正完成后立即显示，不等整篇结束。
2. 启动时固定输入、方向和模型；可以沿用运行中禁用编辑，或用明确的输入快照。旧任务的迟到回调不得修改新任务结果。
3. 复制/导出应使用同一份当次任务结果。修改输入后，不能把上一轮译文当作新输入的翻译。
4. 待处理、处理中、完成、失败以及需要时的“已停止/未完成”数量可核对。结束时仍有失败或未完成段，不能显示“全部翻译成功”。
5. 保留当前结果的原文核对提示；不要将完成状态、数字检查或模型间一致性描述为准确率保证。

### 4.3 停止、失败与重新开始

1. 点击停止后不再启动后续段，取消当前调用，保留已经完整完成的段供阅读、复制和导出。
2. 正在生成但未收到正常完成标记的内容不得记为成功。若显示临时文字，须与完成结果明确区分。
3. 单段错误有清晰状态；独立错误可继续其他段，服务整体不可用则可停止后续调度并保留待处理项。没有无限重试、隐式单段重试或自动重开任务。
4. 本轮不提供“停止后接着翻译”按钮；用户可重新开始一次完整翻译。开始新任务时状态清晰，避免残留旧进度和旧回调。
5. 退出应用不提供自动恢复。调整文字任务退出提示时保留录音已有的保存与退出行为；不要把文字任务描述成可恢复。
6. 保留本机端点、模型校验、响应截断检查和任务取消约束，不结束用户共用的 Ollama 服务。

### 4.4 导出

1. 最低提供双语 TXT：按顺序包含所有原文段和对应已完成译文。
2. 对失败、未开始和停止中断部分，显示明确的“翻译失败/尚未翻译/已停止”等标记，不静默漏段，不把空译文当完整结果。
3. 正常完成和提前停止均可导出；没有译文时也能明确反映原文和未完成状态。
4. 导出是用户主动保存结果，不新增后台自动保存任务库。使用标准保存对话框和现有覆盖文件交互。

## 5. 验收清单

以行为和数据一致性为准，避免大量只复述实现的测试。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 超过 8,000 字符的纯文本 | 可开始，拆成多个有界请求；全部原文和顺序保留；最后完整显示并可导出 |
| 英中与中英 | 两个方向均可使用；方向、模型及结果不会混用 |
| 多段、空行、重复句、缩写、小数、emoji/Unicode | 分段不丢字、不重复原文，不破坏字符；保留可追溯的原文范围 |
| 超长无标点单段 | 能继续拆分并结束，所有请求满足设定预算 |
| 翻译到一半 | 页面已能查看完成段，状态总数一致，停止操作可用 |
| 停止与立即新开一轮 | 已完成内容保留供导出；新任务不会收到旧任务的迟到结果 |
| 单段异常、服务不可用、响应截断 | 不标成成功；保留此前完成结果；失败/未完成标记与导出一致 |
| 双语导出 | 完整任务与部分任务均覆盖全部原文，译文对应正确，无静默缺段 |
| 打包应用 | 新版本/构建号高于现有 build 6，签名通过；真实界面能完成长文翻译、停止及导出 |

自动测试优先用可控翻译器注入延迟、错误与迟到回调。实机至少做一次超过 8,000 字符的本地模型文章翻译，以及另一方向短文、停止后导出的检查；无需做模型质量排名或多次重复推理。测试合成材料可入库，完整个人文章和翻译结果放在忽略目录。
