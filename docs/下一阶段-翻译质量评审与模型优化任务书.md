## 4. 评审样本与评审方法

### 4.1 规模与覆盖

首批约30条样本，建议20条用于诊断/调整、10条独立冻结用于复核；既有问题句必须纳入。开发开始记录清单和用途，不能看过独立复核结果后反复修改样本或计分来掩盖失败。

| 类别 | 必须核对的内容 |
| --- | --- |
| 否定与条件 | not/unless/only if，至少/至多、之前/之后；条件方向和例外不反转 |
| 日期、金额、频率 | 14天、收到/寄出、每天/每次、单位和数量关系；允许写法转换但不能改含义 |
| 学术与课程材料 | 统计限定、专有名词、术语及上下文指代 |
| 重复与遗漏 | 原文重复两次仍保留两次；并列条件、列表项和长段最后一句不静默省略 |
| 英中双向 | 两个方向有足够代表性样本，不能用单向结果代表双向质量 |
| 分段与字幕 | 页/段边界、有限上下文；已核对英文的字幕中文，区分ASR错误 |

优先使用允许公开的自行编写材料和已存在证据。需要用户实际材料时明确请求，不自行查找私人文件。每条记录待保留事实、条件、术语和允许表达差异，不要求逐字匹配唯一参考译文。

### 4.2 评分与可追溯性

分列改变含义的严重错误、影响理解的一般错误和表达问题，记录漏译/多译/条件改变的原文依据。分别报告条目数、错误类型、关键事实覆盖和修正成本，不发布“总体准确率98%”等无依据指标。

评审方式明确标为程序核对、助手逐条语义审阅或用户人工复核；未得到用户复核不能宣称人工验收通过。数字/否定筛查用于发现候选问题，不能替代逐条原文对照；同模型自评和模型间一致性不得作为唯一判断。意见分歧和不确定案例原样记录。

## 5. 有限对照与优化边界

1. 先测0.2.7当前实际配置，保留原结果，再比较现有两套模型。所有模型/GPU任务串行，条件与请求文本一致。
2. 先复现已知问题，再提出少量有依据的提示/参数或分段/有限上下文方案。每次改变记录原因，禁止用删除原文重复、否定、标题或末句“修复”模型漏译。
3. 初轮最多4种完整模型/配置组合，通常为两模型基线与各一组候选；先用诊断样本筛选，再固定方案检查独立样本。不做全参数网格搜索，只有新故障证据才扩大对照并说明必要性。
4. 至少6条关键条件/否定/遗漏样本在基线与拟采用配置下重复3次，记录模型digest、提示版本、参数、seed（若支持）和每次结果。普通样本单次初筛即可，不因单次正确宣布稳定。
5. 保留模型完成标记、响应截断/空结果检查、本机端点和预算。降低随机性不能作为含义错误已修复的证据。
6. 上下文只能来自有限明确来源，仅翻译当前段，保留前段/标题作为辅助证据；不得重复译出上下文或修改源段映射。
7. 阅读与字幕可按实测采用不同默认配置，但仅在必要时新增简单说明，不做复杂自动路由。7B较慢或质量无收益时不强制替换1.8B。
8. 不改变ASR评价。字幕质量评审先使用核对后的已保存英文；新的短字幕请求检查仅验证翻译链路与速度，不能据此宣布课堂或整体语音通过。

## 6. 性能与保存兼容

记录冷启动/预热、首字、完成耗时、吞吐、进程内存、失败/截断和必要的能耗观察。模型加载与推理分开，记录样本长度和调用条件；用中位/P95时给出真实样本数，不将少量数据宣称稳健分布。

阅读默认配置依据保真与等待时间选择；字幕配置必须考虑连续短句请求的完成速度和排队，不能只凭单条翻译速度判断。使用一段有限字幕英文序列做串行排队对照，不启动新的ASR长测。旧延迟数字是模型估计终点，不作真人端到端真值。

0.2.7任务须保存实际提示、参数、模型和分段/上下文版本。新默认只作用于新任务；旧任务打开保留原配置和已完成结果。继续原任务沿用可用的原配置，不隐式混入新参数；用户明确选择新方案时保留旧结果并创建新修订/任务。指纹改变时不把旧译文误认为新配置生成，也不在升级后自动重译历史任务。

字幕配置变更保留成功译文与原文修订/租约规则，迟到旧响应不能覆盖新结果。资源与模型不匹配明确失败，不静默下载或切换模型。源保存的模型digest变化需记录并提示，不把同tag等同于相同权重。

| 自动回归 | 完成/截断、原文预算与保留、配置绑定、旧任务恢复/迟到回调等实际变化有必要检查 |
| 最终包 | 新旧保存任务、英中双向文字、文档/OCR有效文字、字幕补译和导出有限实际操作一致 |
