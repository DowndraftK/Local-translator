# B03 文字层文档的保存与适配约定

本轮从两端实读的 `codex/cross-platform-b01` / `bc31d2b720e66846fce9e17f335fd616cc188233` 接续。实现前明确以下兼容边界，实际候选与验证结果另记于 B03 开发记录和指标。

## 保存兼容

B03 继续采用生产 `TextDocuments` 的 schema1 envelope、Foundation 格式 payload、base64、checksum、current/previous 和单调 revision。文字任务及旧文档不迁移；旧 v1 recipe 省略 contextVersion，原 recipe、binding、保存计划、成功对象和 source 副本保持。新文档使用已有的 DocumentSnapshot/PageRecord/DocumentSource 字段，物理页范围、页修订和页内 UTF-8 半开范围由共享核心验证。旧文档/OCR夹具必须由生产 Swift 编码器生成后冻结。

新文档 `extractionProfile` 记录实际适配器身份。旧 `pdfkit-vision-v1` 可读取、核对已有内容、导出；新后端不兼容时拒绝继续提取，已有计划续译不改分段。新结果不重置来源阅读页。TXT 的内部全文记录不在界面或导出中冒充 PDF 页码。

B04 若需要表示 Windows 不可取得的置信度、带修订归属的草稿等扩展，将在 B03 独立交付后另行登记格式、旧读者拒绝策略和夹具证据；不能让旧应用静默丢失新字段，也不自动迁移旧唯一任务。

## 资源和事实接口

单源文件仍限制 256,000,000 字节，所选连续物理页最多200页，起点可大于200。共享核心保留累计1MiB UTF-8原文、4096段和32MiB快照保护。源文件用64KiB流式复制/hash并封存，原路径仅作记录。缺失或错配副本禁止继续和原页读取，不从原路径补换；已获得内容仍可导出。

Mac 采用窄 PDFKit 适配器，Windows 选择官方 PyPI 的 pypdfium2 5.14.0 / 随附 PDFium。只取得这一 PDF 软件库；无 OCR 模型或语言包下载。固定 wheel、来源、许可、大小和 SHA-256 见 `prototype/b01/pdf-dependencies.lock.json`，二进制与许可全文保留在忽略目录/本地候选，不进源码 Git。PySide6-Essentials 不包含 QtPdf，故不依赖占位 PDF 控件。

适配器仅返回真实页数、页标签/文字及有界渲染事实。页清单、来源、计划、取消、保存恢复、调度和完整TXT导出只有 shared/translator_core 一套。PDF/PNG 不进入 JSONL 帧；来源及每次有界页结果使用受控文件、大小/hash/请求身份校验。渲染每次只保留一页，最长边3000像素、总像素9,000,000、缩放不大于3，处理可见cropBox和PDF旋转。操作完成/取消必须排空后才报告终态。

## B02 必要前置修复

Windows 原桌面验收入口的 LF/中文绝对路径解析失败留原字节证据；新入口使用 ASCII、CRLF 和相对路径。旧验收只结束 Ollama 主进程，遗漏 `llama-server.exe` 模型子进程。修复仅涉及本批自有测试服务：原生 CreateProcessW 暂停创建，先归入私有 KILL_ON_JOB_CLOSE 作业再执行，关闭作业回收全部后代。既有共享/原服务不收编、不卸载模型、不修改全局配置；本修复不算 B08 生命周期专项。
