## 1. 三种内容分别接续

| 内容 | 接续方式 | 事实边界 |
| --- | --- | --- |
| 对话上下文 | 官方Remote连接访问原主机，或Handoff交接到已连接主机 | 取决于两端客户端、账号/工作区和功能开放情况；普通登录不能作为本地旧对话已同步的证明 |
| 源码、任务书、紧凑结果 | 同一Git仓库/接续分支及批次交接记录 | 提交前的Mac本地资料，Windows单纯clone/pull得不到；Git不同步客户端内部对话状态 |
| 运行包、模型、录音、详细证据 | 用户明确传输的独立文件及hash校验 | 不自动进入Git，也不假定Handoff会传输所有忽略文件、运行环境和外部资源 |

推荐官方连接/交接承接完整对话，同时保留Git交接资料作为跨设备持续工作的依据。无需把客户端内部配置、认证或会话数据库目录用网盘互相覆盖。

## 2. 官方连接与对话交接

已查阅官方[Remote connections](https://learn.chatgpt.com/docs/remote-connections)和[Windows desktop app](https://learn.chatgpt.com/docs/windows/windows-app)。官方说明允许从支持的Mac/Windows设备访问另一主机已有项目和对话，Control other devices功能可因开放批次不同而不可见；Handoff可移动对话及Git状态到具有匹配仓库项目的已连接主机。

### 2.1 从Windows访问Mac上的现有对话

两端使用支持相应功能的桌面客户端并登录同一账号/工作区。在Mac的设置→连接中查看“Control this Mac or PC”；在Windows查看“Control other devices”，按客户端界面建立配对。名称和入口以实际版本为准，未见入口时不假定功能可用。

配对成功后，可在Windows访问Mac主机已有项目/对话。此时文件、命令、权限和工具来自Mac，执行仍在Mac；仅从Windows观看Mac任务不构成Windows应用或CUDA实测。

主机应运行客户端、在线并可用。休眠/断网/关闭客户端可能中断远程访问，恢复后再接续。

### 2.2 将本批执行交接到Windows

先在Windows取得同一仓库、保存为本地项目，若项目是仓库子目录则两端保存相同相对子目录；本项目使用仓库根目录。Windows可选路径如 `C:\Projects\Local-translator`，不照搬Mac绝对路径。

将Windows配置为可访问的主机；在批次交接点停止本批测试进程、保存记录及任务副本，然后在桌面客户端对话底部当前运行位置选择目标主机，审核目标项目/分支并执行Hand off。官方说明此操作转移对话与Git状态，在目标创建或复用worktree；运行中交接会中断当前响应，因此优先在批次停止点操作。

确认新的执行主机为Windows，读取本地项目路径、系统/显卡/驱动和源码身份，再执行Windows测试；结果留在该主机任务/文件中。完成后可通过同样方式交接回Mac。当前对话不能由自身调用的交接工具直接迁移，用户可用客户端入口；不因本文存在自动执行交接。

忽略目录中的模型、包、录音和详细日志须单独检查是否已到位，缺失明确提示。Handoff说明仅承诺对话/Git状态，不能把未知的外部资产传输当成已经完成。

### 2.3 可选云模式的边界

官方说明Local computer access with Work Cloud仅适用于启用sync后创建的任务，已有本地任务保持原模式；打开相应设置不能据此认定当前旧对话已转换。该能力与Codex Remote不同，账号/工作区可用性也应以实际界面为准。本项目优先上述连接/交接或下方Git接续，不要求转云或创建付费服务。

## 3. 无Remote/Handoff时：两端独立对话＋Git交接

同一项目可以在两台机器各自的本地对话中接续，前提是把影响实施的事实写进项目资料。Windows新对话读取总任务、分批安排、指定批提示词和上批实际记录即可获得必要上下文；不用复制全部历史聊天。

操作顺序：

1. Mac保存本批交接记录、测试要求和最新源码；按用户授权提交并推送接续分支。编制本文时，新的跨平台/分批资料仍未提交推送，先完成这一步或显式传输这些文件。
2. Windows取得同一仓库与指定分支，确认工作区和本地源码版本，打开本地项目。只做本批Windows适配/测试，依赖/资源未齐时登记，不换模型或降低配置凑结果。
3. Windows把可公开的紧凑测试摘要与必要代码修复写入项目、按授权提交推送；详细日志/截图/材料另存本地忽略目录，必要时由用户明确传输。
4. Mac正常同步该分支，读取Windows测试摘要和修复内容，更新共同矩阵、复验受影响Mac路径，然后判断该批完成范围和下一批前置。

串行交接时可沿一条接续分支工作，避免两端同时修改同一文件并覆盖未提交内容；不要让两台机器同时写一份SQLite任务。显式任务传输用安全关闭/一致备份后的副本，带完整来源和媒体校验。

本文不自动提交/推送或创建新对话。Git源码授权和模型/包/录音等资产传输、二进制公开发布授权分别处理。

## 4. Windows测试应在哪里运行

以Windows原生客户端/原生PowerShell及Windows本地项目运行安装/GUI/WASAPI/权限/DLL/CUDA验收。Windows客户端官方支持原生PowerShell，也可配置WSL；WSL结果不能替代本项目原生Windows安装、麦克风和系统权限证据。

Mac发出指令时，只有执行目标确实为Windows才可登记Windows测试。普通云容器或Mac模拟不能验证该NVIDIA显卡、Windows设备和权限。真人麦克风/休眠由用户主动操作；测试主机休眠使Remote暂时断开是预期连接边界，唤醒后读取实际保存/恢复记录，不能仅凭连接恢复认定录音恢复正确。

B01登记可用Windows主机/项目和实际硬件；B05/B06记录GPU后端与模型资源；B07分别记录真人设备/权限；B09—B12在独立安装位置校验不借开发环境。开发机器可有开发工具，最终应用独立安装要求保持。

## 5. 每批测试交接的最小内容

模板见[Windows测试摘要模板](templates/windows-test-report.template.json)。模板所有结果为未运行或null，不是测试证据；实施时按真实结果另存为批次指标，允许适用新增字段但不能补造数值。

- 批次/测试要求版本、实际本地源码commit、未提交修改是否存在；源码修复后分别记录测试前后身份。
- 实际产品版本、Windows构建/runtime身份、包文件hash和测试入口，不用Mac包路径代替Windows产物。
- Windows版本/架构、CPU/内存、GPU/显存/驱动、真实后端/精度，以及实际模型digest/资源身份。
- 自动检查数量与失败/跳过，有限真实流程、安装/权限/GPU证据和具体未验证原因。
- 内存指标口径、冷暖/空闲条件、当前/峰值/释放和重加载；不可取得的指标标null及原因，不照搬历史。
- 旧成功结果/原文修订/音频/recipe及恢复保护的检查，所有测试进程退出状态与原服务保护。
- 对Mac或共享规则的影响、下一建议批和仍需用户操作/设备/许可/托管条件。

公开Git只存允许的夹具、源码/测试/文档和紧凑结果；私有路径、完整用户材料、凭据、数据库、录音和详细日志不纳入。实际详细证据路径在本机记录或经用户明确传输，不要求公开上传。
